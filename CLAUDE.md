# Focus Lock — Website Time Box

A Chrome extension (Manifest V3) that puts distracting websites in a "time box,"
the way a phone-jail safe locks a phone away on a timer. The user lists sites,
sets a duration, and during that window the sites are hard-blocked behind a lock
screen with a live countdown. Optionally they can "earn" their way in by solving
a deliberately tedious captcha gauntlet followed by an "are you sure?" confirmation.

## Product decisions (these shape the code — don't quietly reverse them)

- **Lock model: soft / honor-system.** Locks and schedules stay freely editable;
  the value is friction, not an unpickable vault. Don't add hardening
  (incognito coverage, anti-uninstall, password gating) without an explicit ask.
- **Two timer types:** one-off *focus sessions* (set from the toolbar popup) and
  *recurring schedules* (managed on the options page).
- **Block behavior:** hard block by default → a landing page with countdown.
  An "I really need to visit" escape opens the captcha challenge.
- **Challenge escape outcome:** solve the captcha N times → a final "Are you sure?"
  → **Yes** unlocks that site for the *rest of the current timer/window*;
  **No** returns to the lock screen with the remaining time and the option to retry.
- **Design language: calm & minimal.** Warm paper background, sage-green accent,
  generous whitespace, gentle/encouraging copy. Never alarming red — use the muted
  clay `--danger` for the "unlock anyway" affordance only.
- **Matching is domain-wide.** Blocking `youtube.com` also blocks every subdomain
  and path (channels, `m.youtube.com`, `/watch?...`).

## Architecture

Plain JS + HTML + CSS, no build step. Load unpacked via `chrome://extensions`.

| File | Role |
|------|------|
| `manifest.json` | MV3 manifest. Permissions: `storage`, `tabs`, `webNavigation`, `alarms` + `<all_urls>` host access. |
| `common.js` | Shared layer used by **both** the service worker (`importScripts`) and every page (`<script>`). Hangs everything off `self.FocusLock`. Owns the storage schema, domain/schedule helpers, the `evaluate()` "is this URL locked?" core, `unlock()`, and formatters. **Put shared logic here.** |
| `background.js` | Service worker. Only three jobs: (1) intercept navigations via `webNavigation.onBeforeNavigate` / `onHistoryStateUpdated` and redirect locked tabs to `blocked.html`; (2) keep the toolbar badge count fresh; (3) `chrome.alarms` "tick" every minute to drop expired locks. Does **not** edit locks. |
| `popup.html/.css/.js` | Toolbar popup. Stage a list of sites + pick a duration → write block entries. Lists what's locked right now with live countdowns and an "End" button for sessions. |
| `blocked.html/.css/.js` | The lock screen the tab gets redirected to. Three views: **lock** (countdown), **challenge** (captcha ×N), **confirm** ("are you sure?"). Reads `?d=&key=&until=&from=` from its URL. |
| `options.html/.css/.js` | Recurring schedules CRUD + settings (challenge on/off, captcha repetitions). |
| `theme.css` | Design tokens (CSS variables) + base element styles, shared by all pages. |
| `icons/` | PNG icons (16/48/128), generated by a one-off `System.Drawing` PowerShell script. |

### Data model (chrome.storage.local)

```
blocks:          [{ id, domain, label, endTime, createdAt, unlockedUntil }]
schedules:       [{ id, domain, label, days:[0-6], start:"HH:MM", end:"HH:MM" }]
scheduleUnlocks: { [scheduleId]: timestampMs }   // unlocked until this time
settings:        { captchaRounds: 10, challengeEnabled: true }
```

- A **session** unlock sets `block.unlockedUntil = block.endTime`.
- A **schedule** unlock sets `scheduleUnlocks[id] = end-of-current-window`.
- `days` uses JS `Date.getDay()` numbering: `0 = Sunday`.

### Key data flows

- **Blocking:** `background.js` → `FocusLock.evaluate(url)` → if locked, redirect the
  tab to `blocked.html` with the domain, lock `key`, `until` timestamp, and original
  `from` URL as query params.
- **Unlocking:** `blocked.js` calls `FocusLock.unlock(key)` directly (pages have full
  storage access), then redirects to `from`. No message passing — UI pages read/write
  `chrome.storage.local` themselves; the worker only reads during navigation.

## Conventions

- All cross-context logic goes through `self.FocusLock` in `common.js`. The popup,
  options, and lock pages talk to storage directly; reserve `background.js` for
  navigation interception, badge, and cleanup.
- Normalize any user-entered site with `FocusLock.normalizeDomain()` before storing
  (strips protocol/path/`www.`/port). Match hosts with `FocusLock.hostMatches()`.
- Keep copy calm and second-person ("your focus," "keep me focused"). No guilt, no red.

## Testing locally

1. `chrome://extensions` → enable Developer mode → **Load unpacked** → select this folder.
2. Add a site in the popup, lock it for a few minutes, visit the site → expect the lock screen.
3. Try "I really need to visit" → solve the captchas → confirm **No** (returns) and **Yes** (unlocks for the rest of the timer).
4. After an edit, hit the **reload** ↻ on the extension card to pick up changes.

There is no build, lint, or test command — it's vanilla extension code.
